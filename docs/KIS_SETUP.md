# 한국투자증권(KIS) 모의투자 연결 체크리스트

실제 돈을 넣기 전에 이 순서를 그대로 따라가세요. 각 단계는 앞 단계가 끝나야 의미가 있습니다.

## 0. 준비물

- 한국투자증권 계좌(종합계좌). 모의투자는 계좌가 있어야 신청할 수 있습니다.
- Python 3.12, 이 저장소, `pip install -r requirements.txt` 완료.

## 1. KIS Developers 가입과 키 발급 (약 10분)

1. https://apiportal.koreainvestment.com 접속 → 로그인 → "API 신청".
2. **모의투자** 용 앱을 하나 만듭니다. 실전용 앱은 나중에 따로 만듭니다(키가 다릅니다).
3. 발급된 **App Key**, **App Secret** 을 복사해 둡니다. 화면을 닫으면 Secret 은 다시 볼 수 없습니다.
4. 포털의 "모의투자" 메뉴에서 모의투자 계좌를 신청합니다. 계좌번호는 `12345678-01` 형식(8자리-2자리)입니다.

## 2. 설정 파일 (약 3분)

```
copy config.example.toml config.toml
```

`config.toml` 에서 아래만 바꿉니다.

```toml
[live]
broker = "kis"
tickers = ["069500.KS", "229200.KS", "114260.KS"]   # 처음엔 국내 ETF 2~3개로
strategy = "ensemble"

[kis]
app_key = "발급받은 App Key"
app_secret = "발급받은 App Secret"
account_no = "12345678-01"
mode = "vts"            # 반드시 vts(모의투자)로 시작

[risk]
max_order_value = 1000000   # 1회 주문 100만 원 한도. 모의여도 습관을 들입니다.
```

키를 파일에 두기 싫으면 환경변수 `KIS_APP_KEY`, `KIS_APP_SECRET`, `KIS_ACCOUNT_NO` 로 줄 수 있습니다. `config.toml` 은 git 에 올라가지 않습니다.

## 3. 연결 확인 (주문 없음)

```
python cli.py live check
```

기대 결과:
- `연결 OK: kis (vts) 실계좌=False`
- 현금(모의투자 초기 자금)과 보유 종목이 보임
- 종목별 현재가가 숫자로 나옴

실패하면:
| 메시지 | 원인 |
|---|---|
| `KIS 토큰 발급 실패` | 키 오타, 또는 모의투자 키를 실전 서버(prod)에 쓴 경우. `mode` 확인 |
| `rt_cd=1 ... 계좌` 관련 | 계좌번호 형식(8자리-2자리) 또는 모의투자 계좌 미신청 |
| `현재가를 받지 못했습니다` | 장 운영 시간 외에는 일부 조회가 0 을 돌려줄 수 있음. 평일 09:00~15:30 에 재시도 |
| `거래소 코드를 모릅니다` | 미국 종목이 기본 목록에 없음. `[kis.us_exchange]` 에 추가 |

## 4. dry-run (주문 계산만)

```
python cli.py live run
```

- "주문 계획" 과 "시장 추세 필터" 상태, "오늘이 리밸런스 날인지" 를 읽어 봅니다.
- 주문 금액이 `max_order_value` 를 넘으면 거부 사유가 보입니다. 한도를 조정하거나 그대로 둡니다.

## 5. 모의투자에 실제 전송

```
python cli.py live run --execute
```

- 실계좌(prod)가 아니므로 확인 질문 없이 바로 전송됩니다.
- 결과의 `✔ BUY ... #주문번호` 를 KIS 모의투자 화면(HTS/MTS 또는 포털)에서 대조합니다.
- `python cli.py live status` 로 로그를 확인합니다. 로그 원본은 `live_log/날짜.jsonl`.

## 6. 매일 자동 실행 (2~4주)

방법 A: 터미널을 켜 두고
```
python cli.py live schedule --at 15:20 --execute --yes
```

방법 B: Windows 작업 스케줄러에 평일 15:20, 프로그램 `run_live.bat`, 인수 `--execute --yes` 로 등록.

이 기간 동안 확인할 것:
- 매일 로그가 쌓이는가 (빠진 날이 있으면 스케줄러 문제)
- 주문 거부(✖)가 반복되는가 → 리스크 한도나 현금 부족
- "데이터가 오래된 종목" 노트가 자주 뜨는가 → 실행 시각을 더 늦추기
- 백테스트 기대치와 크게 다른 체결가가 있는가 (지정가/시장가 설정 확인)

## 7. 실전 전환

모의투자에서 위 항목이 모두 안정적이면:
1. KIS 포털에서 **실전용 앱**을 새로 만들어 키를 발급받습니다.
2. `config.toml` 의 `[kis]` 를 실전 키·실전 계좌번호로 바꾸고 `mode = "prod"`.
3. `[risk]` 를 다시 봅니다. `max_order_value`, `max_position_weight`, `max_daily_loss_pct` 는 실제 금액 기준으로 보수적으로.
4. `python cli.py live check` → `live run`(dry-run) → `live run --execute` (이번엔 `yes` 확인 질문이 뜹니다).
5. 처음 몇 주는 소액으로. 문제가 생기면 `python cli.py live stop` 으로 즉시 모든 주문을 막을 수 있습니다.

## 자주 묻는 것

- **왜 오늘은 주문이 없나요?** 보고서의 "오늘은 리밸런스 날이 아닙니다" 노트를 보세요. 기본 전략은 월 4번(월말, +5, +10, +15 거래일)만 비중을 바꿉니다. 그 사이에는 비중 차이 2% 미만이라 주문이 안 나갑니다.
- **왜 현금이 많나요?** "시장 추세 필터 … 현금 (OFF)" 이면 묶음 전체가 200일선 아래라 전략이 의도적으로 피한 것입니다.
- **국내와 미국을 한 설정에 섞어도 되나요?** 통화가 섞여 현금 계산이 틀어집니다. 설정 파일을 나눠 `--config` 로 따로 실행하세요.
- **이 연동은 검증됐나요?** 코드는 KIS 공식 문서 기준으로 작성되고 가짜 응답으로 테스트됐지만, 실서버 호출은 사용자 환경에서 처음 일어납니다. 그래서 3단계 `live check` 가 필수입니다. 응답 필드명이 다르면 `quant/broker/kis.py` 의 `ENDPOINTS` 와 파싱 부분만 고치면 됩니다.
